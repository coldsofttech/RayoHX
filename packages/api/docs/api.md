# API

`rayohx_api` is a FastAPI app over `rayohx`. It runs on its own on any system, and the same routes are mounted inside the UI window (see [UI](../../../docs/ui.md)). Routes only validate input, call the library and shape the response; logic stays in `rayohx`. For how the pieces fit together, see [architecture](architecture.md); to work on the API, see [development](development.md).

## Running it

```bash
cp .env.example .env              # set RAYOHX_API_API_KEYS, or RAYOHX_API_AUTH_MODE=none
uv run python -m rayohx_api      # http://127.0.0.1:8000
```

The app refuses to start without an API key unless authentication is switched off. This is on purpose, so the API is never open by accident. See [security](security.md).

## Settings

Read from `RAYOHX_API_*` environment variables or a `.env` file. List values are JSON.

| Variable | Default | Purpose |
| --- | --- | --- |
| `RAYOHX_API_HOST` | `127.0.0.1` | Address to listen on |
| `RAYOHX_API_PORT` | `8000` | Port to listen on |
| `RAYOHX_API_LOG_LEVEL` | `info` | Log level |
| `RAYOHX_API_AUTH_MODE` | `api_key` | `api_key`, or `none` for local development |
| `RAYOHX_API_API_KEYS` | none | Accepted keys, sent in the `X-API-Key` header |
| `RAYOHX_API_DOCS_ENABLED` | `false` | Serve `/docs`, `/redoc` and `/openapi.json` |
| `RAYOHX_API_MAX_BODY_BYTES` | `1048576` | Largest request body |
| `RAYOHX_API_CORS_ORIGINS` | none | Origins allowed by CORS |
| `RAYOHX_API_DOWNLOAD_DIR` | `~/Downloads/RayoHX` | Folder downloads are saved in (clients choose file names only) |
| `RAYOHX_API_MAX_ACTIVE_DOWNLOADS` | `2` | Downloads that run at once; the rest queue |
| `RAYOHX_API_DEFAULTS_FILE` | per-user config folder | Where default options are saved (`rayohx/api-defaults.json`) |
| `RAYOHX_API_ALLOW_LOCAL_PATHS` | `false` | Let requests name files on the server: cookie files, CA bundle, client certificate and key, FFmpeg, `file:` keys. Leave off for a network service; the window turns it on |

## Endpoints

| Method and path | Purpose |
| --- | --- |
| `GET /health`, `GET /ready` | Liveness and readiness probes, no authentication |
| `POST /api/v1/inspect` | Variants and tracks of a playlist, from an address or from playlist text plus `base_url` |
| `GET`/`POST /api/v1/downloads` | List jobs, or start one per address (`url`, `urls`, or `playlist_text` with `base_url`) (202) |
| `GET`/`DELETE /api/v1/downloads/{id}` | One job, or forget a finished one |
| `POST /api/v1/downloads/{id}/pause`, `/resume`, `/cancel` | Control a job |
| `GET /api/v1/downloads/{id}/events` | Server-sent `job` events until the job ends |
| `GET /api/v1/settings` | Server settings and the saved default options |
| `PUT /api/v1/settings/defaults` | Replace the default options (saved to disk; logins and passwords are never saved) |
| `GET /api/v1/downloads/{id}/log` | What the engine reported for a job (the CLI's `--events` stream, without per-segment noise) |
| `POST /api/v1/clean` | Remove leftover working folders in the download folder (`dry_run` by default) |

Jobs live in memory and are lost when the process stops; the engine resumes partial files. Signed-URL tokens are removed from every address returned. Errors use the problem-details format (`application/problem+json`).

## The contract

[`openapi.json`](openapi.json) is generated by `uv run python packages/api/scripts/export_openapi.py`. CI fails when it is out of date, `api-compat.yml` warns about breaking changes on pull requests, and a Schemathesis test fuzzes the running server for server errors. Put breaking changes in a new `/api/v2` router.

## Options

`POST /api/v1/downloads` takes the same options as the command line, grouped as `network`, `selection`, `storage`, `output` and `engine`; see `openapi.json` for every field. Options left out use the saved defaults, then the engine's own. Sizes are in bytes, bitrates in bits per second. Folders (`output.directory`, `storage.workspace`) are relative to the download folder and cannot leave it. Several addresses in `urls` are named after their addresses, as `rayohx download` does.

Not offered: `--events` and `--json` formatting, pause by signal, and the settings file `rayohx.toml`; they belong to the terminal. The API keeps its own defaults file instead.
